- `package_id`: WP-09
- `goal`: 维护者可在 Umami Cloud 后台查看正式站点的页面访问分析。
- `owner`: 项目维护者
- `scope`: `src/lib/analytics*.js`、`src/app.js`、`index.html`、相关隐私/架构/部署文档
- `non_goals`: 自建后台、用户身份识别、搜索或提示词采集、点击事件埋点。
- `dependencies`: Website ID 已配置；GitHub Pages 推送和 `ui.saveas.me` 部署仍待完成。
- `acceptance`: 留空 Website ID 时无统计请求；填写 ID 后只在允许域名加载 tracker；hash 页面访问进入后台；DNT 和查询参数排除生效；页脚与配置说明揭示数据边界。
- `status`: active
- `blocker`: 线上 Realtime 验收尚未完成。Sites Version 15 已发布；GitHub Pages 仍需推送根目录改动，自有服务器仍需部署更新后的静态文件。

## 后续扩展顺序

1. 维护者体验首版：逐个走一遍案例选择、推荐变化、示例操作和复制指令；记录小白不理解的表达。
2. 修订种子内容：优先处理选项歧义、实际业务上下文不足、模式解释不清楚等问题。
3. 继续增加案例：先补新手需求说法，再判断已有模式是否可复用；避免为了新增案例重复造术语。
4. 增加内容校验：当案例数量让人工核对引用变得不可靠时，校验重复 ID、无效 family/pattern/demo 引用和不可达分支。
5. 评估静态生成：当需要可索引的独立内容页或 hash 路由维护成本明显增加时，再迁移生成型静态方案。

## 验收门

- **内容门**：问题答案真实改变组件推荐；未回答时展示候选而不假定用户意图；推荐理由用用户能理解的话书写。
- **交互门**：案例详情可回答问题、查看推荐理由、操作示例、修改并复制指令；术语可以反向找到相关案例。
- **俗语门**：读者能从“弹框”“文本框”等日常说法进入，一屏比较多种带名称的可操作效果；按需展开解释、适用场景和注意点，并复制中文叫法优先的指令。
- **导航与帮助门**：顶部是唯一的主浏览导航，按“按需求找、按俗语找、按术语找、按场景找、帮助说明”排序，并显示四类内容的动态数量；帮助页为贡献者和 AI 提供字段、关联、编辑和核对约定。
- **人工体验门**：使用键盘和窄屏走查主要流程；检查焦点、表单标签、菜单/对话框关闭方式和动态状态反馈。
- **公开项目门**：README、贡献方式、仓库可见性及许可证安排对新贡献者清楚。

当前未完成的门：真实浏览器人工走查、屏幕阅读器体验、许可证决定。未执行自动化测试或构建检查。
