# 说准一点 · UI Words

> 面向 AI Coding 新手的互动教程：从“加个弹窗”“做个选择框”这样的产品说法出发，弄清用户目标，再找到更准确的交互做法。

“弹窗”可能是短暂出现的 Toast、需要用户处理的 Modal Dialog、重要操作前的 Alert Dialog、保留列表上下文的 Drawer，或贴着按钮出现的 Popover。这个项目帮助新手看见这些差异，再把需求写成 AI 更容易实现的指令。

## 现在有什么

- **按需求找**：从 17 类常见用户目标进入，不需要预先知道术语。
- **按俗语找**：从 128 个日常说法与情境表达出发，比较它们可能对应的做法。
- **按术语找**：用中文叫法浏览 72 种交互模式，需要时再查英文标准名和官方依据。
- **按场景找**：浏览 161 个有官方设计指南依据的需求情境；按 8 条服务任务脉络浏览或搜索后，回答关键问题并比较可行做法。
- **帮助说明**：为内容维护者和 AI Coding 助手提供六类数据对象的字段、关联规则、编辑流程和核对清单。
- **访问分析（维护者）**：启用 Umami Cloud 后，在其统计后台查看页面访问量、来源、设备和大致地区；站内搜索词与 AI 指令不作为统计事件发送。
- **先看效果，说明按需展开**：俗语详情以更紧凑的多列效果卡展示更多选择；点开“了解这个效果”再看影响、场景、注意点和可复制说法。
- **一对多推荐**：回答问题后查看合适的交互模式、理由和相近做法。
- **动手试一试**：在页面中操作 HTML 示例，了解输入、选择、加载、反馈和浮层如何回应。
- **带走一条指令**：先用自然中文说清界面做法、使用场景和交互细节；需要时再查专业名称。

顶部导航是唯一的全站内容浏览菜单。四个浏览入口的数量从对应 JSON 数据自动读取；新增场景可按任务脉络筛选，场景和模式详情附有官方参考来源。内容语句是参考指南后的编辑性示例，除非标出研究证据，不代表访谈原话。

## 本地运行

需要用本地静态服务器打开页面（案例和术语内容通过 JSON 加载）：

```sh
python3 -m http.server 8000
```

然后访问 <http://localhost:8000>。本地小型 HTTP 服务只负责提供静态文件（浏览器需要通过 HTTP 读取案例 JSON）；部署时可直接把项目文件放到 GitHub Pages 或其他静态文件托管服务。项目不需要应用后端、数据库、构建步骤、UI 框架或 npm 依赖。访问统计是可选的第三方脚本，仅在配置 Umami 网站 ID 后加载。

网站由传统 HTML/CSS 和少量原生 JavaScript 构成。JavaScript 负责案例筛选、条件推荐、交互预览、复制指令和可选的页面访问统计；所有教程内容仍是仓库中的静态文件。Umami 接入和后台设置方法见[访问分析配置说明](docs/analytics-setup.md)。

## 内容和代码

页面交互和案例内容分开维护，新增案例不需要改页面代码：

- `src/data/families.json`：按新手目标划分的场景入口。
- `src/data/cases.json`：需求情境、任务脉络、澄清问题、推荐分支和来源 ID。每个推荐分支引用一个主要模式、可选辅助模式和替代模式，并说明理由。
- `src/data/journeys.json`：服务任务脉络及其说明。
- `src/data/sources.json`：去重的官方设计系统参考链接。
- `src/data/colloquialisms.json`：俗语、常见变体、澄清问题，以及对应的多个模式和案例。
- `src/data/patterns.json`：交互模式的中文叫法、专业名称、适用边界和示例指令。
- `src/lib/decision-engine.js`：根据回答匹配内容中的推荐分支。
- `src/lib/demo-catalog.js`：根据模式 ID 选择可交互的本地 HTML 示例。
- `src/lib/prompt-builder.js`：优先用中文叫法，将用户目标、场景、模式效果和边界组装成可编辑指令。
- `src/app.js`：网站导航、内容呈现和交互状态。

增加案例的方法和字段约定见 [贡献指南](CONTRIBUTING.md)。产品流程和内容模型见[系统设计](docs/system-design.md)，当前实现边界见[架构基线](.engineering/architecture-baseline.md)。
