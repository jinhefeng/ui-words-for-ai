# 说准一点 · UI Words

> 面向 AI Coding 新手的互动教程：从“加个弹窗”“做个选择框”这样的产品说法出发，弄清用户目标，再找到更准确的交互做法。

“弹窗”可能是短暂出现的 Toast、需要用户处理的 Modal Dialog、重要操作前的 Alert Dialog、保留列表上下文的 Drawer，或贴着按钮出现的 Popover。这个项目帮助新手看见这些差异，再把需求写成 AI 更容易实现的指令。

## 现在有什么

- **按需求找**：从 8 个常见产品场景进入，不需要预先知道术语。
- **17 个种子案例**：每个案例从一句新手说法开始，提出一个会改变实现方式的澄清问题。
- **一对多推荐**：回答问题后查看合适的交互模式、理由和相近做法。
- **动手试一试**：在页面中操作 HTML 示例，了解输入、选择、加载、反馈和浮层如何回应。
- **带走一条指令**：生成可编辑、可复制的 AI Coding 指令。
- **术语索引**：按英文名、中文叫法或口语别名搜索 32 个交互模式，并跳回相关案例。

## 本地运行

需要用本地静态服务器打开页面（案例和术语内容通过 JSON 加载）：

```sh
python3 -m http.server 8000
```

然后访问 <http://localhost:8000>。也可以部署到 GitHub Pages 或其他静态文件托管服务。项目不需要账号、后端、数据库、构建步骤或第三方依赖。

## 内容和代码

页面交互和案例内容分开维护，新增案例不需要改页面代码：

- `src/data/families.json`：按新手目标划分的场景入口。
- `src/data/cases.json`：口语需求、澄清问题和推荐分支。每个推荐分支引用一个主要模式、可选辅助模式和替代模式，并说明理由。
- `src/data/patterns.json`：交互模式术语、中文叫法、适用边界和示例指令。
- `src/lib/decision-engine.js`：根据回答匹配内容中的推荐分支。
- `src/lib/demo-catalog.js`：根据模式 ID 选择可交互的本地 HTML 示例。
- `src/lib/prompt-builder.js`：将用户目标、场景、模式和边界组装成可编辑指令。
- `src/app.js`：网站导航、内容呈现和交互状态。

增加案例的方法和字段约定见 [贡献指南](CONTRIBUTING.md)。产品流程和内容模型见[系统设计](docs/system-design.md)，当前实现边界见[架构基线](.engineering/architecture-baseline.md)。
